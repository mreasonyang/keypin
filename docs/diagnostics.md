# 本地诊断日志

设置 → **打开诊断日志…**，打开 `~/Library/Logs/KeyPin/`。

基本状态日志默认开启，代码不主动上传。**“记录应用标识”默认关闭**：此时既不查询、也不写入其他应用的 PID、bundle ID 或占用者信息。当前文件为 `diagnostics.jsonl`；轮转后依次为 `diagnostics.1.jsonl`、`diagnostics.2.jsonl`。每份最多 512 KiB，总计最多 1.5 MiB，写满后淘汰最旧文件。

按每条记录的时间保留 7 天，混合文件中的旧记录也会移除，不以文件修改时间代替记录时间。首次写入、打开日志文件夹和关闭应用标识选项时执行清理；GUI 运行时每小时巡检一次（调度可略有延迟），因此安静期间也会清理。应用退出、系统睡眠期间不运行清理；恢复运行后再执行。损坏、未知 schema 和异常未来时间戳会被丢弃。

文件夹权限为 `0700`，日志为 `0600`。这些权限限制其他普通用户读取，同一用户或管理员仍可能访问；应用不加密日志。默认记录仍包含时间、KeyPin 自身 PID、运行状态与版本信息，不能描述为完全没有隐私信息。

每行是一个 schemaVersion 为 1 的 JSON 对象，包含 UTC 时间、GUI 会话 ID、KeyPin PID 和固定事件类型。日志按状态变化记录，不为每两秒的稳定轮询写一行。

| 事件 | 说明 |
| --- | --- |
| `session_started` / `session_ended` | GUI 启动和正常退出，以及版本、构建号、macOS 版本；异常退出可能没有结束记录 |
| `runtime_changed` | 界面状态、是否保持、目标是否可用、当前是否匹配目标、配置是否异常发生变化 |
| `secure_input_started` | 首次观察到安全输入，创建 episode ID；启动时已经开启则标记 `activeAtSessionStart` |
| `secure_input_context_changed` | 安全输入持续期间，前台应用或系统报告的占用信息改变 |
| `secure_input_still_active` | 首次持续 30 秒后补记，此后最多每 5 分钟补记一次 |
| `secure_input_ended` | 观察到安全输入已关闭，记录同一 episode 的已观察持续时间 |
| `switch_completed` / `switch_recovered` | 手动切换结果、自动切换失败及恢复；相同自动失败去重，正常自动轮询成功和忙碌不刷屏 |
| `events_suppressed` | 超出写入额度时，后续汇总各事件类型被省略的次数及最新状态，不缓存每条原文 |

每个 GUI 进程在任意滚动 60 秒内最多输出 60 条：普通事件最多使用前 40 个额度，为会话、安全输入边界和恢复预留 20 个。极端情况下关键事件也可能超额，不能承诺逐条保留；60 秒后有额度时合并输出省略次数及最新状态。限额在进程内维护，重启会重置。正常稳定轮询不写日志；安全输入持续不变时仍按 30 秒、之后每 5 分钟低频补记。磁盘待写队列最多 64 条，慢盘时进一步丢弃新增记录，避免内存无限增长。

持续时间使用单调时钟，不受修改系统时间影响；它是**被 KeyPin 观察到的持续时间**，精度受轮询周期和系统调度影响。启动前的时长未知；睡眠和进程退出期间没有连续观测保证。应用退出时仍开启安全输入，只记录会话结束，不伪造安全输入已释放。

只有主动开启“记录应用标识”后，安全输入记录才可能包含以下两个独立信息；采样最多每 2 秒一次：

- `frontmostApplication`：观察时的前台应用 PID 与 bundle ID，是排查线索，**不代表占用者**。
- `systemReportedOwner`：尽力读取当前用户、当前控制台会话的系统报告 PID，并在可用时附带 bundle ID。该 IORegistry 元数据没有稳定的公开契约，可能缺失、过时或无法代表全部持有者。`ownerLookup` 明确标记 `reported_pid` 或 `unavailable`，不会用前台应用填补未知占用者。

该选项保存在应用自身的 UserDefaults，键为 `diagnosticsIncludeApplicationMetadata`，不改变输入法配置。关闭后立即停止新增采集，并异步清理当前三份日志中的应用标识；写入边界还会再次检查开关，避免排队中的旧事件带入标识。清理失败会明确提示，不能声称旧数据已全部移除。清理不涉及已分享的副本、系统备份或 APFS 快照，也不是磁盘安全擦除。主动开启后，应用 ID 和时间可能反映应用使用行为；若 ID 自身包含内部项目名称等信息，也会随元数据记录。

开启选项后，应用只通过 NSWorkspace/NSRunningApplication 和指定 IORegistry 属性读取这些元数据，不运行进程列表工具，不读取 argv、环境或认证存储。日志不记录按键、输入文本、密码、剪贴板、窗口标题、文档/网址、输入源名称/ID、任意错误消息或完整路径。切换错误只保存固定类型和数值状态码；版本字符串也限制为数字和点，拒绝夹带任意文本。这是限制采集面的设计，不是能识别所有秘密的通用脱敏器。

写入通过独立串行队列完成。磁盘满、权限错误、异常文件类型或链接会使写入失败，但不会阻塞或停止输入法保持；每轮连续写入故障只向系统日志提示一次固定错误。正常退出等待待写事件完成；不承诺断电时的磁盘持久化。CLI、焦点辅助进程和隔离预览不创建独立日志会话，也不与 GUI 竞争轮转。

排查时先按时间与 episode ID 筛选安全输入的开始、持续、结束，再对照 `snapshot.state`、切换返回码及恢复事件。分享前检查应用使用元数据，仅提供相关时间段，不直接转发全部日志。旧版未记录的事件无法通过升级补回。
