# KeyPin

**中文** · [English](README.en.md)

**锁定 Mac 输入法，跨 App 保持一致。**

KeyPin 是一款轻量的 macOS 菜单栏工具。在不同应用（如终端、编辑器、浏览器与聊天软件）之间切换时，KeyPin 能自动检测输入源变化并尝试切回你预设的目标，减少频繁手动切换输入法的打扰。

> **系统要求**：macOS 13 或更高版本，Apple silicon 或 Intel Mac。Universal 安装包同时包含两种架构。macOS 26+ 使用 Liquid Glass，旧系统使用原生普通材质与按钮。界面支持简体中文、繁體中文、English、日本語和 한국어。

[官网](https://keypin.kyun.si) · [版本与下载](https://github.com/mreasonyang/keypin/releases) · [问题反馈](https://github.com/mreasonyang/keypin/issues)

## 使用指南

### 菜单栏交互

1. **初次配置**：启动 KeyPin，从系统已启用的输入法中选择保持目标，并确认是否立即启用保持及登录时启动。
2. **日常切换**：点击菜单栏上的输入法图标，即可快速切换目标或暂停保持。

| 操作需求 | 操作方式 | 说明 |
| --- | --- | --- |
| **保持特定输入法** | 在面板列表中点击该输入法 | 立即切换至该输入法并开启自动保持 |
| **临时自由切换** | 选择列表首项「跟随系统」 | 暂停自动保持，记住已存目标，不改变当前输入法 |
| **登录时自动运行** | 进入「设置」开启「登录时启动」 | 用户登录 Mac 后在后台启动并在菜单栏常驻 |
| **修改界面语言** | 进入「设置」选择偏好语言 | 支持 5 种语言切换 |
| **退出应用** | 点击主面板底部的「退出」 | 关闭主窗口仍会在菜单栏常驻运行 |

### 图标与状态反馈

- **图标指示**：菜单栏展示系统当前实际生效输入法的自带图标（若该输入法无可用图标，则回退为键盘图标）；处于「跟随系统」时，图标呈半透明变淡效果。
- **勾选与当前**：开启保持时，勾选标记（✓）指示保持目标；暂停时，勾选标记移至「跟随系统」。「当前」标签则始终实时标出系统正在生效的输入源。
- **冲突退让**：同一 App 内短时间反复切换时，KeyPin 会暂缓保持并显示可重试提示，避免持续争抢输入法或焦点。持续冲突会延长等待；切换 App 或主动重试可恢复。

更详细的面板布局、引导状态与界面机制请参阅 [界面与行为参考](docs/behavior.md)。

## 安装与运行

### 使用预编译应用包

从[官网](https://keypin.kyun.si)直接下载 GitHub Releases 上的 Universal DMG，同一个安装包适用于 Apple silicon 和 Intel Mac。打开 DMG 后，将 `KeyPin.app` 拖入 `Applications` 快捷方式。然后：

1. 将应用移至准备长期放置的目录（建议置于「应用程序」`/Applications`）。若需开启「登录时启动」，请务必在移动位置后再开启。
2. 双击打开即可开始使用。

> [!NOTE]
> 正式版本由 GitHub Actions 完成 Developer ID 签名和 Apple 公证后发布。尚无正式 Release 时，请等待发布或从源码构建。Actions 中标注 development 的包和本地默认构建仅为 ad-hoc 签名，不代表已通过公证或实机验收。

### 应用内更新

在「设置 > 关于」中点击「检查更新」，可通过 Sparkle 从 GitHub Releases 检查、下载并安装新版本。自动检查与自动下载安装默认关闭，可以分别在关于页启用。安装与重启由 Sparkle 管理；更新保留输入法配置和登录启动设置。

未配置更新公钥的本地开发包会显示更新不可用。旧的 0.0.14 及更早版本没有应用内安装更新能力，需要手动安装第一个支持自动更新的正式版本。

### 从源码编译

要求环境具备包含 **macOS 26 SDK** 的 Xcode / Swift 工具链：

```sh
./scripts/package.sh
open ./build/KeyPin.app
```

编译生成物位于 `build/KeyPin.app`。日常使用无需强制安装命令行工具或开启登录项。

## 命令行操作

KeyPin 应用包内置了完整 CLI。在尚未配置终端快捷命令前，可直接调用包内可执行文件执行查询：

```sh
"./build/KeyPin.app/Contents/MacOS/keypin" list
"./build/KeyPin.app/Contents/MacOS/keypin" status --json
```

### 首次配置终端入口

若希望直接在终端使用 `keypin` 用户命令，先通过上文的 `list` 命令获取可用输入源 ID，然后从应用包内运行 `install`（以常见系统输入法 ID 为例）：

```sh
# 将 com.apple.keylayout.ABC 替换为 list 命令中查到的目标 ID
"./build/KeyPin.app/Contents/MacOS/keypin" install "com.apple.keylayout.ABC"
```

> [!NOTE]
> `install` 命令会**同时设定保持目标、启用保持状态、注册当前用户登录项并在 `~/.local/bin/keypin` 建立符号链接**。
> 该命令仅在当前用户作用域生效，不会修改系统级目录或 `PATH` 环境变量；请确保 `~/.local/bin` 已加入你的 `PATH`，否则仍需使用完整路径调用。

### 常用命令速查

在 `keypin` 可用后，常用子命令如下：

| 命令 | 说明 |
| --- | --- |
| `keypin status` | 查看当前状态（输入法、保持目标、运行状态等） |
| `keypin list` | 列出系统中所有可用的输入源 ID 与名称 |
| `keypin pause` | 暂停保持（保留当前保持目标，不切当前输入法） |
| `keypin resume` | 恢复保持意图（若 GUI 未运行，仅写配置而不拉起应用） |
| `keypin toggle` | 切换保持状态（开 / 关） |
| `keypin set <id>` | 设定保持目标并立即切换一次（保留原有保持开关） |
| `keypin apply` | 按已保存的保持目标再次尝试切换（仍受安全输入等系统限制） |
| `keypin open` | 打开应用的主设置窗口 |
| `keypin install <id>` | 设定目标、开启保持、注册登录启动并建立 CLI 链接 |
| `keypin uninstall` | 注销登录启动项并停止后台代理（保留配置与 CLI 链接） |

### 脚本与自动化

除 `help` 外，所有命令均支持 `--json` 选项（例如 `keypin status --json`）。

在 `--json` 模式下：

- 成功退出码为 `0`，失败退出码为 `1`。
- 标准输出只输出单个 JSON 对象。
- `list --json` 成功时返回 `sources` 数组；其他状态查询或修改命令成功时返回 `status` 对象；操作失败时返回包含机器可读代码的 `error` 对象（含 `code` 与 `message`）。
- 自动化脚本应判断 `ok` 与 `error.code`，请勿依赖普通文本模式下的本地化提示。

完整命令参数、JSON 数据结构、错误码与路径定义详见 [命令行与配置参考](docs/cli.md)。

## 隐私与数据安全

- **完全本地运行**：KeyPin 不需要账户，所有输入源切换、调度与设置均在本地完成。
- **更新联网**：正式版在手动检查更新，或用户启用自动检查后，连接 GitHub 及其资源分发服务获取更新信息和安装包。更新使用 Sparkle 验证签名；不启用系统信息统计，不上传输入内容或输入法配置。未配置公钥的本地开发包不启动更新服务。
- **配置存储**：用户配置以 JSON 格式存储于：

  ```
  ~/Library/Application Support/KeyPin/config.json
  ```

  包含目标输入源 ID、保持状态、语言偏好与引导完成标记。所有配置写入均采用文件互斥锁与原子保存。

## 兼容性与限制

- **输入源依赖**：KeyPin 仅能选择已在系统「设置 > 键盘 > 输入法」中启用并可用的输入源。若目标输入源被系统移除，KeyPin 会报告错误并等待重新指定。
- **安全输入（Secure Input）**：当系统处于密码输入框等安全输入上下文时，KeyPin 会暂缓切换，待安全环境解除后再行调度。
- **中日韩及越南文输入源**：此类输入源的切换依赖微型焦点辅助机制。由于各第三方应用对输入焦点的响应存在差异，跨 App 真实输入法行为仍建议实际体验验证。
